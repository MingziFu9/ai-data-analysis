## 课程与学习方法 { #faq-1 }

??? question "以前几乎没学过编程，能学会这门课吗？"

    能。本课程不要求你从零写出复杂的程序，“能看懂、会运行、会修改”就够了。标 ★ 的实验都给出了完整代码和运行结果，你要做的是读懂每一行在做什么、运行它、再按“运行并修改”改一改参数。建议开课前用 6 个小时左右学完[附录 A](../appendix/a-python.md)，第 2 章再把 Python 和 pandas 的基础系统地过一遍，后面各章用到的写法都可以在[附录 B](../appendix/b-libraries.md) 里查到。

??? question "这门课和“人工智能导论”“机器学习”“大数据技术”等课是什么关系？"

    本课程专讲**数据**：怎样采集、清洗、标注、分析和展示数据，怎样维护上线后的智能系统，怎样合规地使用数据，对应“人工智能训练师”岗位的主要工作。“机器学习”课专讲算法原理，本书第 9、10 章只用 scikit-learn 做几个应用，不讲算法推导；“大数据技术”课讲海量数据的存储和分布式计算，本书的数据都在一台电脑上就能处理。

??? question "每章三个实验都要做吗？"

    标 ★ 的基础实验建议都做，标 ☆ 的拓展实验可以课后选做。实验学时不够时，教师会从中指定。每个实验末尾的“实验记录表”和“实验报告要求”就是要交的作业。第 12 章的综合项目分组完成，贯穿最后几周，详见 [12.6 节](../chapters/12-ethics-project/index.md#126)。

??? question "怎样用好在线练习和交互动画？"

    每章的单选、多选、判断题可以在网页上直接点击作答，答错了点“回看”链接跳回正文。交互动画嵌在正文中，也可以从[交互动画](../sims/index.md)页单独打开，建议先按动画下方的提示操作一遍，再自己改参数观察变化。[学习图谱](../learning-graph/index.md)可以帮你查某个概念要先懂哪些概念。

??? question "怎样准备期末考试和职业技能证书考试？"

    期末为开卷考试，可以带教材和笔记，但题目侧重理解和应用，临时翻书来不及，平时要把实验做扎实。课后练习的五种题型与证书理论考试的题型一致，网站上的[在线模拟卷](../mock-exam.md)可以用来自测。各证书的考点和本书章节的对应关系见[证书考点对照](../certificate.md)，正文中的“证书考点”提示框标出了常考点和易错点。

## 数据处理基础 { #faq-2 }

??? question "数据分析、数据处理和数据标注有什么区别？"

    数据处理是把原始数据变成“能用的数据”，包括采集、清洗、整合、转换；数据标注是给数据加上标签，让模型能从中学习；数据分析是从数据中找出规律、得出结论、支持决策。三者在实际项目中前后衔接，详见 [1.2 节](../chapters/01-overview/index.md#12)。

??? question "Excel 也能做表格，为什么还要学 pandas？"

    数据量大（几万行以上）时 Excel 会变慢甚至打不开；同样的处理每个月都要重做一遍时，pandas 写一次代码就能反复运行，不会点错；清洗、合并、统计的每一步都写在代码里，别人可以检查和复现。第 2 章把常用的 Excel 操作逐个对照成 pandas 的写法，见 [2.2 节](../chapters/02-pandas/index.md#22-excel-pandas)。小数据、一次性的查看，用 Excel 或 WPS 的数据透视表同样很好（[8.3 节](../chapters/08-visualization/index.md#83-bi)）。

??? question "两张表合并以后，行数怎么变多了？"

    右表中用来匹配的键有重复，左表的一行匹配上了右表的好几行，就会“一变多”。合并前先用 `duplicated()` 检查键是否唯一，合并后核对一下行数，详见 [2.5.3 节](../chapters/02-pandas/index.md#253)。

??? question "缺失值是删掉好，还是填上好？"

    先看缺了多少、缺在哪、为什么缺，再决定。缺得很少且随机，可以删；关键字段缺失，可以按组用中位数填充并加一列标记；缺失本身有含义（比如“没有优惠”），就保留或填成一个明确的值。不要不看原因就一律删除或填平均数，详见 [4.3 节](../chapters/04-cleaning/index.md#43)。

??? question "异常值都要删掉吗？"

    不一定。异常不一定是错误：一单 2000 元可能是多人聚餐的真实大单，删掉反而会让分析失真。先用 3σ 法则或箱线图法找出“离群”的值，再结合业务判断它是录入错误、系统错误还是真实的极端情况，分别修正、置为缺失或保留，详见 [4.4 节](../chapters/04-cleaning/index.md#44)。

??? question "清洗数据为什么还要写规范？代码不就是规范吗？"

    代码只说明“怎么做”，规范还要说明“为什么这样做”，并且让不看代码的人（需求方、后续使用者、接手的同事）也能看懂和检查。规范写清楚判断方法、处理方式和理由，换一个人照着做，结果也应当一样，详见 [4.7 节](../chapters/04-cleaning/index.md#47)，模板见[附录 E](../appendix/e-templates.md)。

??? question "数据类型分那么多种，有什么用？"

    不同类型的数据，处理和分析的方法不同：数值型可以求平均，类别型只能计数；结构化数据直接用表格处理，评论、图片这类非结构化数据往往要先标注或转换。拿到数据先判断类型，才知道下一步该做什么，详见 [1.3 节](../chapters/01-overview/index.md#13)。

## 数据采集 { #faq-3 }

??? question "打开 CSV 文件，中文全是乱码，怎么办？"

    乱码是因为“用错误的编码去读文件”。Excel 另存的 CSV 常常是 GBK 编码，读的时候写 `pd.read_csv(文件, encoding="gbk")`；自己保存的文件写 `encoding="utf-8-sig"`，用 Excel 打开就不会乱码，详见 [3.2.1 节](../chapters/03-collection/index.md#321-csv)。

??? question "网页上公开的数据，是不是就可以随便爬？"

    不是。要遵守网站的 robots 协议和用户协议，控制访问频率不能影响网站正常运行，不能绕过登录、验证码等技术措施，不能采集个人信息和受保护的内容，采集的数据也不能随意转卖或公开。能用开放接口取数时，优先用接口，详见 [3.5 节](../chapters/03-collection/index.md#35)。

??? question "调用接口时返回状态码 429，是什么意思？"

    429 表示“请求太频繁”，触发了接口的限流。在两次请求之间加上等待（`time.sleep`），遇到 429 或 5xx 错误时等一会儿再重试，不要立刻反复请求，详见 [3.4.4 节](../chapters/03-collection/index.md#344)。

??? question "接口的密钥可以直接写在代码里吗？"

    不可以。代码会被分享、上传到代码仓库，写在里面的密钥很容易泄露。密钥应当放在环境变量或单独的配置文件里，配置文件不要提交到仓库，详见 [3.4.2 节](../chapters/03-collection/index.md#342)。

## 数据标注 { #faq-4 }

??? question "做数据标注需要会编程吗？"

    标注本身主要在 Label Studio 这样的工具里点选和划框，不需要编程。但人工智能训练师不只是标注，还要设计标签体系、编写规范、检查质量、把标注结果转换成训练数据，这些工作会用到 Python 和 pandas，详见 [1.4 节](../chapters/01-overview/index.md#14)。

??? question "标注规范要写多细才够？"

    写到“两个标注员拿到同一条数据，按规范能标出同样的结果”为止。每个标签要有定义、正例和反例，拿不准的情况要写成边界规则。规范不是一次写成的：先试标，统计分歧最大的地方，再补充规则，详见 [5.4 节](../chapters/05-annotation/index.md#54)。

??? question "Kappa 系数多少才算合格？"

    常用的参考标准是：0.81 以上几乎完全一致，0.61～0.80 较强，0.41～0.60 中等，0.40 以下较弱。一般要求达到 0.6 以上，要求高的任务要 0.8 以上。Kappa 低时，首先要检查的是规范是否说清楚了，而不是先怪标注员，详见 [6.1.2 节](../chapters/06-annotation-qa/index.md#612-kappa)。

??? question "抽检抽多少才够？"

    本书的做法是按标注员分层抽 10%，准确率不低于 95% 为合格，不合格再加抽。抽得越少，误判越多：可能把合格的批次判为不合格，也可能放过不合格的批次。重要的数据和新标注员的数据应当多抽，详见 [6.2 节](../chapters/06-annotation-qa/index.md#62)。

??? question "用模型预标注，会不会把标注员“带偏”？"

    会有这个风险：标注员看到模型给的答案，容易不仔细看就点“确认”，模型的错误就被保留下来了。所以预标注的数据也要照常抽检，并定期混入一些没有预标注的数据，比较两者的准确率，详见 [6.5 节](../chapters/06-annotation-qa/index.md#65)。

??? question "大模型这么厉害，以后还需要人工标注吗？"

    需要，但工作重点在变。大模型可以做预标注，把简单的数据先标好，人工负责审核、处理疑难样本、编写规范；大模型本身的训练也需要大量的指令数据和偏好数据，这些都要人来编写和评判。会用大模型提高标注效率，同时能判断它哪里错了，是新的岗位要求，详见 [5.1.2 节](../chapters/05-annotation/index.md#512)和 [9.6 节](../chapters/09-modeling/index.md#96)。

## 统计分析与可视化 { #faq-5 }

??? question "平均数和中位数，用哪个？"

    数据大致对称时两者差不多；数据有少数特别大的值（如订单金额、收入）时，平均数会被拉高，中位数更能代表“一般水平”。报告中最好两个都给出，详见 [7.1.1 节](../chapters/07-statistics/index.md#711)。

??? question "两个变量的相关系数很高，能说明一个导致了另一个吗？"

    不能。相关只说明两者一起变，可能是第三个因素同时影响了两者，也可能只是巧合。比如用了优惠券的顾客复购率高，可能不是优惠券让顾客回头，而是平台本来就更愿意给老顾客发券。要证明因果，需要 A/B 测试这样的实验，详见 [7.3.2 节](../chapters/07-statistics/index.md#732)。

??? question "p 值小于 0.05，说明差别很大吗？"

    不是。p 值小只说明“差别不太可能是碰巧”，不说明差别有多大、有没有业务价值。样本很大时，很小的差别也会显著；反过来，p 值大也不能证明“没有差别”，可能只是样本太少。读检验结果时要同时看差别的大小和置信区间，详见 [7.5.4 节](../chapters/07-statistics/index.md#754)。

??? question "什么时候用饼图？"

    只在表示“各部分占整体的比例”、而且类别不超过 5 个时用。类别多了，各块大小很难比较，改用条形图。比较多少用条形图，看趋势用折线图，看分布用直方图或箱线图，看关系用散点图，详见 [8.1 节](../chapters/08-visualization/index.md#81)。

??? question "纵轴不从 0 开始，一定是误导吗？"

    条形图的纵轴必须从 0 开始，因为人是按条的长度比较大小的，截断纵轴会把小差别放大成大差别。折线图看的是变化趋势，纵轴可以不从 0 开始，但要标清刻度。详见 [8.4 节](../chapters/08-visualization/index.md#84)。

## 建模与推荐 { #faq-6 }

??? question "准确率很高，就是好模型吗？"

    不一定。如果九成评论都是正面，模型全部猜“正面”准确率也有九成，但一条负面评论都找不出来。要看混淆矩阵和每一类的精确率、召回率，还要和“全部猜最多的类”这样的基准比，详见 [9.4.2 节](../chapters/09-modeling/index.md#942)。

??? question "为什么一定要把数据分成训练集和测试集？"

    模型在训练过的数据上表现好，不代表在新数据上也好，就像背过答案的题考得好不代表真会。要用模型没见过的测试集来评估，而且测试集的信息不能以任何方式“泄露”到训练过程中，详见 [9.1.2 节](../chapters/09-modeling/index.md#912)。

??? question "新用户、新店铺没有历史数据，怎么推荐？"

    这就是冷启动问题。新用户可以先推荐热门的、离他近的店，或者让他选几个感兴趣的菜系；新店铺可以按它的城区、菜系、价格找相似的店，借用它们的数据，也可以给新店一些曝光机会。实验 10-3 中，给新用户推荐“本区热门”的命中率比“全站热门”高很多，详见 [10.5.2 节](../chapters/10-recommendation/index.md#1052)。

??? question "推荐系统会把人“困”在信息茧房里吗？怎么避免？"

    有这个风险：系统只推荐你爱看的，你看到的就越来越窄。常用的办法是在推荐结果中加入一定比例的新内容和多样的内容，评估时除了命中率还要看覆盖率，并允许用户关闭个性化推荐。《互联网信息服务算法推荐管理规定》对此有明确要求，详见 [10.6.3 节](../chapters/10-recommendation/index.md#1063-ab)和 [10.7 节](../chapters/10-recommendation/index.md#107)。

## 运维与合规 { #faq-7 }

??? question "模型没有改过，上线一段时间后为什么效果变差了？"

    因为数据变了。用户的说法、行为、业务规则都会随时间变化，模型却还停留在训练时的样子。输入的分布变了叫数据漂移，输入和标签的关系变了叫概念漂移。要用监控指标和 PSI 定期检查，发现问题后补标、重训，详见 [11.3 节](../chapters/11-operations/index.md#113)。

??? question "PSI 多大需要警惕？"

    经验标准是：小于 0.1 稳定；0.1～0.25 有变化，需要关注；大于 0.25 变化显著，需要排查。PSI 只说明分布变了，变了是否影响模型效果，还要抽检准确率才知道，详见 [11.3.2 节](../chapters/11-operations/index.md#1132-psi)。

??? question "手机号打了星号、用户编号做了哈希，数据就不算个人信息了吗？"

    仍然算。这叫去标识化，结合其他信息还有可能认出是谁，比如“性别 + 年龄段 + 城区 + 注册日期”的组合可能是唯一的。只有处理后无法识别特定个人、而且不能复原，也就是匿名化，才不再属于个人信息，详见 [12.4.3 节](../chapters/12-ethics-project/index.md#1243)。

??? question "能把用户数据发给大模型，让它帮忙分析吗？"

    不能直接发含有个人信息的数据。发给外部服务就是向第三方提供个人信息，需要有合法依据。可以先脱敏，或者只告诉大模型列名和结构、让它写代码，代码在自己电脑上运行。公司的数据还要遵守公司的规定，详见 [12.2 节](../chapters/12-ethics-project/index.md#122)。

??? question "哈希为什么要加“盐”？"

    手机号只有 11 位，攻击者可以把所有可能的手机号都算一遍哈希，对照着就能反查出原号码（“撞库”）。哈希前拼接一段只有自己知道的字符串（盐），别人不知道盐，就没法这样反查。盐要像密码一样保管，不能和数据放在一起，详见 [12.4.1 节](../chapters/12-ethics-project/index.md#1241)。

## 实验环境与排错 { #faq-8 }

??? question "没有显卡、电脑配置一般，能做实验吗？"

    能。本书全部实验都在普通笔记本电脑的 CPU 上测试过，最慢的也在一分钟左右。电脑配置很低的，可以用云 Notebook 平台，详见[附录 C](../appendix/c-environment.md)。

??? question "程序报错了，怎么办？"

    先看报错信息的**最后一行**，判断是哪种错误；再看它指出的行号，检查那一行和上一行。常见的错误类型和改法见[附录 A 的 A.10 节](../appendix/a-python.md#a10)，每个实验末尾的“常见问题排查”表列出了这个实验最常见的报错。还解决不了，把完整的报错信息和代码复制给大模型或老师。

??? question "提示 FileNotFoundError，找不到数据文件？"

    最常见的原因是没有在实验所在的文件夹里运行。先用 `cd labs/ch07` 这样的命令进入对应章节的文件夹，再运行程序。用 Jupyter 的同学，把 Notebook 文件也放在那个文件夹里。

??? question "提示 ModuleNotFoundError，说某个库不存在？"

    这个库没有安装，或者装在了另一个环境里。先确认已经激活了本课程的虚拟环境（命令行行首有环境名），再运行 `pip install 库名`。注意有的库导入名和安装名不同：`import sklearn` 要安装 `scikit-learn`。

??? question "图上的中文显示成一个个方框？"

    Matplotlib 没有找到中文字体。检查画图代码开头是否有设置中文字体的两行；Linux 和云平台要先安装中文字体。运行时出现的 `findfont` 警告可以忽略，详见[附录 C 的 C.3 节](../appendix/c-environment.md#c3)。

??? question "Label Studio 打不开，或者打开后是空白页？"

    确认启动它的命令行窗口没有关闭，并且已经出现“Starting development server”一类的提示，第一次启动要等一两分钟；端口被占用时，用 `label-studio start --port 8081` 换一个端口。不想装 Python 的，可以用 Docker 启动，详见[附录 C 的 C.4 节](../appendix/c-environment.md#c4-label-studio)。

??? question "我的运行结果和书上的数字有一点不一样，是做错了吗？"

    大多数实验用了固定的随机种子，结果应当和书上一致。如果只是最后一两位小数不同，通常是库的版本不同造成的，不影响结论；如果差别很大，检查是否修改了代码、数据文件是否完整，或者是不是先运行了别的实验改动了数据。

??? question "书上标着“待实测”的实验是什么意思？"

    这些实验需要下载预训练模型或调用大模型 API，编者的编写环境无法访问，所以没有给出运行结果，而是附了一张记录表，请你运行后自己填写。它们都是选做的拓展内容，不做不影响后面的学习，详见[附录 C 的 C.6 节](../appendix/c-environment.md#c6)。
