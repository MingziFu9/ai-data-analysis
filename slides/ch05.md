# 5.1 为什么人工智能需要标注数据

## 模型从“题目 + 答案”中学习
| 任务 | 题目（输入） | 答案（标签） |
|---|---|---|
| 评论情感分析 | 一条评论 | 正面 / 负面 / 中性 |
| 菜品识别 | 一张菜品照片 | 菜品名称 |
| 餐具检测 | 一张餐桌照片 | 每个碗、盘、杯的框 |
| 语音点餐 | 一段录音 | 对应的文字 |

::: notes
这种学习方式叫监督学习，答案就是标签，给数据加标签就是数据标注。
:::

## 大模型也离不开标注
- **指令数据**：写出“问题 + 高质量的回答”
- **偏好数据**：几个回答按规范排出好坏
- 标注从“选标签”变成“写和评”
- 对标注员的语言能力、专业知识要求更高

# 5.2 常见的标注任务

## 文本分类与实体标注
- **单标签**：整体情感只能选一个
- **多标签**：涉及的方面可以选多个
- **实体标注**：划出菜品名称
- **BIO**：B 开头、I 中间、O 不是实体
- “水煮鱼很好吃” → B I I O O O

## 动手试：实体标注与 BIO
!sim entity-bio
- 用鼠标划出实体
- 看每个字的 BIO 标签

## 图像标注
| 类型 | 标注结果 | 难度 |
|---|---|---|
| 图像分类 | 整张图一个类别 | 低 |
| 目标框标注 | 每个物体一个矩形框 | 中 |
| 图像分割 | 沿轮廓的多边形 | 高 |
| 关键点标注 | 若干特定点的位置 | 高 |

::: notes
画框四原则：贴紧、不漏、一物一框、类别正确。
:::

# 5.3 设计标签体系

## 标签体系的三个要求
- **互斥**：单选标签之间不能重叠
- **完整**：每条数据都能找到标签
- **粒度合适**：太粗没信息，太细分不清
- “其他”类要有定义，定期检查
- 本书：情感（单选）+ 方面（多选）+ 菜品（实体）

::: notes
证书考点：训练师四级数据标注。常考标签体系的设计原则，以及给一段文本按 BIO 标注。
:::

# 5.4 编写标注规范

## 规范的组成部分
- 任务说明、标签定义
- **正例和反例**：是什么、不是什么
- **边界规则**：分歧几乎都出在边界上
- 疑难样例、质量要求
- 版本记录：规范会不断修订

## 边界规则举例
- 好坏都有：**看结尾的总结表态**
- 没有表态、好坏各半 → 中性
- 😋👍 视为正面表态，😡👎 视为负面
- “上菜很快”属服务，“送得很快”属配送
- 只有“[手机号]”：中性，点跳过

::: notes
用三个疑难样例带学生练：“骑手送错地址。三文鱼刺身味道很正宗”标中性；“口味不行，不过价格实惠 失望”标负面；“……叫了三次都没人理，五星好评😋”标正面。完整规范见 labs/ch05/标注规范_v1.0.md。
:::

## 先试标，再定稿
- 抽 50～100 条，两三人**各自独立**标
- 实验 5-1：50 条中 36 条一致，一致率 **72%**
- 列出分歧，讨论：粗心还是规范没写清？
- 补边界规则，再试标一批
- 情感分类一般要达到 85%～90% 以上

::: notes
交叉表的对角线是两人一致的。甲标正面、乙标负面的 4 条，往往就是“好坏都有”的评论，正是边界规则要补的地方。
:::

# 5.6 把标注结果变成训练数据

## 同一个框的两种写法
| 格式 | 写法 | 含义 |
|---|---|---|
| 参考答案 | 426, 8, 524, 106 | 左上角、右下角（像素） |
| COCO | [426, 8, 98, 98] | 左上角 x、y，宽、高 |
| YOLO | 2 0.742 0.119 0.153 0.204 | 类别，中心点和宽高（比例） |

::: notes
图片宽 640、高 480。YOLO 的中心点 x = (426+524)/2/640 = 0.742。JSON 导出用循环转成一行一条的训练表。
:::
