# 12.1 数据工作中的伦理问题

## 三个案例
- **大数据杀熟**：老用户看到的价格更高
- **标注数据泄露**：带个人信息的数据流出
- **样本偏差导致不公平**：模型对一部分人不准
- 合法不等于合理：伦理要求更高
- 数据从业人员要有“守门”意识

## 个人信息与敏感个人信息
- **个人信息**：与已识别或可识别的自然人有关
- 单独能认出：姓名、手机号、身份证号、地址
- 组合能认出：性别 + 年龄段 + 城区……
- 和用户编号连在一起的订单、评论也算
- **敏感个人信息**：身份证号、银行账户、行踪轨迹、健康……

## 处理个人信息的基本原则
- **知情同意**：告知目的、方式、范围
- **最小必要**：不多拿、不多用、不多存
- **公开透明**：公开隐私政策
- **保证安全**：加密、去标识化、权限
- **保存期限**：到期删除

# 12.3 数据分类分级

## “食客说”的数据分类分级
| 数据 | 级别 | 保护措施 |
|---|---|---|
| 商家名录、菜系、价格 | 低 | 可以公开 |
| 订单汇总统计 | 中 | 内部使用 |
| 评论内容 | 中 | 脱敏后标注、分析 |
| 用户编号与订单明细 | 高 | 去标识化，按需授权 |
| 姓名、手机号、地址 | 很高 | 加密，严格审批 |

# 12.4 脱敏方法

## 四种常用方法
| 方法 | 例子 | 适合 |
|---|---|---|
| 掩码 | 130****0103 | 页面展示、客服核对 |
| 哈希（加盐） | U00002 → f95cb3a3486d | 关联多张表 |
| 泛化 | 详细地址 → 天河区 | 统计分析 |
| 扰动 | 金额 ±5% | 只关心总体统计 |

::: notes
哈希为什么要加盐：手机号只有 11 位，攻击者可以把所有手机号都算一遍哈希来“撞库”。盐要像密码一样保管，不能和数据放在一起。
:::

## 脱敏后照样能分析
- 各区用户数：脱敏前后**完全相同**
- 金额扰动：平均 133.17 → 133.14 元
- 但要检查**准标识符**组合
- 性别 + 年龄段 + 城区：0% 独一无二
- 再加注册日期：**94.3%** 独一无二！

::: notes
去标识化后的数据仍是个人信息，结合其他信息还有可能认出是谁。把注册日期泛化到年份后，独一无二的用户降到 0.1%。只有无法识别且不能复原的匿名化数据，才不再属于个人信息。
:::

# 12.5 算法偏见与样本偏差

## 偏差从数据中来
- 只用**平台专送**的订单训练送达时间模型
- 平台专送：平均误差 3.49 分钟
- 商家自送：平均误差 5.25 分钟，**系统性少估 4.49 分钟**
- 商家自送迟到 10 分钟以上的占 9.8%
- 总体准确不等于对每一群人都准

## 怎样发现偏差
- 检查数据的**代表性**
- **分组评估**模型
- 检查**标注**的偏差：方言、网络用语
- 检查结果的**影响**：谁总是得到更差的服务
