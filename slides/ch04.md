# 4.1 数据质量：从哪几个方面检查

## 数据质量的六个维度
| 维度 | 问的问题 | 订单表的例子 |
|---|---|---|
| 完整性 | 有没有缺？ | 没有配送距离 |
| 唯一性 | 有没有重复？ | 同一单两行 |
| 有效性 | 格式、范围对不对？ | 日期写法不一 |
| 一致性 | 各处记录一致吗？ | “天河”“天河区” |
| 准确性 | 符合真实情况吗？ | 金额按“分”录入 |
| 及时性 | 够不够新？ | 混进了别的年份 |

## 实验 4-1：质量评估表（节选）
| 维度 | 检查项 | 问题行 | 占比 |
|---|---|---|---|
| 有效性 | 下单时间格式不标准 | 697 | 8.58% |
| 一致性 | 城区不在标准列表中 | 635 | 7.82% |
| 有效性 | 配送距离不是数字 | 364 | 4.48% |
| 完整性 | 配送距离为空 | 315 | 3.88% |
| 唯一性 | 完全重复的行 | 120 | 1.48% |
| 有效性 | 送达时长为负数 | 22 | 0.27% |

::: notes
8120 行原始订单按六个维度共查了 13 项。把每项检查写成一条规则（条件），用循环统计问题行数和占比。正式的数据质量评估报告模板见附录 E.2。证书考点：训练师四级业务数据处理。
:::

# 4.2 重复值与主键

## 重复值与主键
- **主键**：能唯一标识一行的列，如 order_id
- 主键不能为空、不能重复
- **完全重复**：整行一样，直接删除
- **主键重复但内容不同**：先查原因再决定
- `duplicated()`、`drop_duplicates()`

# 4.3 缺失值：删、填，还是留着

## 先问为什么缺
- 系统没记录？用户没填？本来就没有？
- 优惠金额为空 = 没有优惠 → 填 0
- 缺失**有没有规律**：只缺远距离订单？
- 有规律时直接删，会让结果**偏**

## 四种处理方法
| 方法 | 适用 | 风险 |
|---|---|---|
| 删除 | 缺得少、无规律 | 丢信息、可能有偏 |
| 填固定值 | 空值有明确含义 | 用错就错 |
| 填统计值 | 数值列，缺得不多 | 分布变“尖” |
| 按组填充 | 同组的值相近 | 仍是估计值 |
| 保留为“未知” | 类别列 | 统计时要单独处理 |

::: notes
按组填充：配送距离按城区中位数填，比全表中位数更合理。填充后加一列“是否填充”的标记，让后面的人知道这是估计值。
:::

# 4.4 异常值：异常不一定是错误

## 两种找“离群值”的方法
- **3σ 法则**：离平均值超过 3 个标准差
- **箱线图法**：超出 Q1 − 1.5×IQR 或 Q3 + 1.5×IQR
- 实付金额：3σ 找出 163 行，箱线图找出 463 行
- 数据**不对称**时两种方法差别很大
- **业务规则校验**往往更可靠

::: notes
3σ 找出的大单，就餐人数大多是 4 人，是多人聚餐的真实大单，不是错误。所以统计方法只能“找出来”，是不是错误要结合业务判断。
:::

## 先问为什么，再决定怎么办
| 情况 | 例子 | 处理 |
|---|---|---|
| 确定是错，能找回真实值 | 时长为负（符号录反） | 改正 |
| 确定是错，找不回 | 送达 600 分钟 | 置为空 |
| 真实但极端 | 4 人火锅 900 元 | 保留 |
| 拿不准 | 新店一天 300 单 | 标记，问业务 |

# 4.5 格式与单位统一

## 写法、单位、类型
- `.str.strip()` 去空格，`.str.removesuffix("区")`
- `"3.2km"` → `.str.replace("km", "")`
- `pd.to_numeric(..., errors="coerce")` 转数字
- `pd.to_datetime` 统一日期
- 按“分”录入的金额：找出来再 ÷ 100

::: notes
实验 4-2 中按分录入、已换算的有 93 行，按业务规则修正优惠金额 24 行，负数改正 22 行，超长置空 27 行。
:::

# 4.6 文本清洗与正则表达式

## 评论里的“脏东西”与正则表达式
| 写法 | 意思 | 例子 |
|---|---|---|
| \d{11} | 连续 11 个数字 | 手机号 |
| 1[3-9] | 方括号里任选一个 | 13～19 |
| ！{2,} | 至少重复 2 次 | 一串感叹号 |
| 竖线 | a 或者 b | 加微信 或 代写好评 |
| ^ $ | 开头、结尾 | 末尾的空白 |

::: notes
评论里的脏东西：广告、手机号、网页残留标签、重复标点、表情。手机号不要直接删，替换成“[手机号]”，标注员知道这里原来有个号码。
:::

# 4.7 清洗规范：让别人照着就能做

## 清洗规范与清洗流水线
- 每条规则：**查什么、怎么判断、怎么处理、为什么**
- 配一份更新后的**数据字典**
- 把每一步写成**函数**，按顺序调用
- 清洗前备份，清洗后**核对**
- 模板见附录 E.3

::: notes
实验 4-2 清洗后与编者准备的标准答案逐项比较，下单时间、实付金额、优惠金额一致率都是 100%。核对的意识比代码本身更重要。
:::
