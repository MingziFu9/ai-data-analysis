# 3.1 数据从哪里来

## 常见的数据源
| 数据源 | “食客说”的例子 | 常见形式 |
|---|---|---|
| 业务系统 | 下单系统、商家后台 | 数据库表 |
| 日志 | 点击、搜索、运行日志 | 文本、JSON 行 |
| 开放接口 | 地图、天气服务 | JSON |
| 文件 | 商家名录、财务报表 | CSV、Excel |
| 网页 | 公开新闻、公告 | HTML |

## 采集方式怎么选
- ① **找人要文件**：最简单，问清口径
- ② **从数据库取数**：申请只读权限，写 SQL
- ③ **调用接口**：按接口文档调用
- ④ **网页采集**：前三种都没有时才考虑
- 优先级从上到下

::: notes
证书考点：训练师四级业务数据采集。技能考核常给一个业务需求，要求说出数据源、采集方式并写出采集方案。
:::

# 3.2 文件采集：CSV、Excel、JSON 与 Parquet

## 乱码是怎么来的
- **UTF-8**：国际通用，一个汉字 3 个字节
- **GBK**：老的中文编码，一个汉字 2 个字节
- 用 UTF-8 去读 GBK 文件 → **UnicodeDecodeError**
- 解决：`encoding="gbk"`，不行试 `"gb18030"`
- 自己保存给 Excel 看：`encoding="utf-8-sig"`

::: notes
现场演示 labs/data/ch03/商家名录_gbk.csv：不写编码直接读，报错；加上 encoding="gbk" 正常。“乱码”不是数据坏了，是读的方式错了。
:::

## Excel、JSON、Parquet
- Excel：`sheet_name=None` 读全部工作表
- JSON：一层套一层，`json_normalize` **展平**
- Parquet：列式存储，**文件小、读得快、保留类型**
- CSV 最通用，Parquet 适合大数据量

::: notes
Excel 最常见的坑是只读了第一个工作表。JSON 展平后列名会变成 shop.shop_id 这样的形式。
:::

## 四种文件格式对比
| 格式 | 记录类型 | 文件大小 | 适合 |
|---|---|---|---|
| CSV | 否 | 大 | 交换数据、给人看 |
| Excel | 部分 | 中 | 手工维护、多工作表 |
| JSON | 部分 | 大 | 接口返回、嵌套结构 |
| Parquet | 是 | 小 | 大数据量存储和分析 |

# 3.3 从数据库取数：SQL 入门

## SQL 与 pandas、Excel 对照
| 想做的事 | SQL | pandas |
|---|---|---|
| 选几列 | SELECT 列1, 列2 | df[[…]] |
| 筛选 | WHERE 条件 | df[条件] |
| 分组统计 | GROUP BY 列 | groupby |
| 排序 | ORDER BY 列 DESC | sort_values |
| 两表关联 | JOIN … ON … | merge |

## 用 pandas 执行 SQL
```python
import sqlite3
conn = sqlite3.connect("../data/ch03/shike.db")
sql = """SELECT order_id, 实付金额 FROM orders
         WHERE 天气 = '雨' AND 送达时长 > 45"""
df = pd.read_sql(sql, conn)
```
- SQL 里等于只写**一个**等号，文字用单引号

::: notes
SQL 关键字习惯大写。时间范围写成“大于等于月初、小于下月初”更稳妥。连接 MySQL 只需换连接方式，SQL 写法基本相同。
:::

# 3.4 开放接口：一页一页地取数据

## 一次请求和它的回答
| 状态码 | 含义 | 怎么办 |
|---|---|---|
| 200 | 成功 | 读取数据 |
| 401 / 403 | 没有权限 | 检查密钥 |
| 404 | 地址不存在 | 检查网址 |
| 429 | 请求太频繁 | 等一会儿再试 |
| 500 / 503 | 对方出错 | 等一会儿再试 |

::: notes
口诀：2 开头成功，4 开头是自己的问题，5 开头是对方的问题。密钥放环境变量，不写进代码。
:::

## 做一个“有礼貌”的采集程序
- **分页**：每页 100 条，一页一页取
- **限流**：两次请求之间 `time.sleep`
- **重试**：遇到 429、5xx 等一会儿再试
- **采集日志**：记录每次采了什么、哪里出错
- **增量采集**：只取上次之后的新数据

::: notes
实验 3-3 的结果：第一天共 113 页、11226 条；第二天增量采集只要 8 页、新增 774 条，累计 12000 条。
:::

# 3.5 网页采集与合规边界

## 网络爬虫与 robots 协议
- 请求网页 → 解析 HTML → 找下一页 → 存表
- **robots.txt**：网站告诉爬虫哪些能采
- `Disallow`：不允许，`Allow`：允许
- 遵守 robots 是**底线**，不是许可证

## 哪些不能做
- **不绕过**登录、验证码、频率限制
- **不采集个人信息**
- **不影响**网站正常运行
- **不“搬运”**别人积累的内容
- 有疑问先问法务，留下书面意见

::: notes
回到情景导入：爬竞争对手的评论，涉及大量用户昵称（个人信息）和对方积累的内容，即使网页公开也有很大法律风险。可行的做法是用公开报告、第三方合规数据，或者只做人工抽样浏览。证书考点：数据处理工程师（中级）网络爬虫，容易错在认为“公开的就能随便爬”。
:::

# 3.6 写一份采集方案

## 采集方案要回答的问题
- 采集目的、需要哪些数据
- 数据源和方式、时间范围、数据量
- 频率与时间
- **合规与安全**：最容易被忽略
- **质量检查**：条数对得上、编号不重复
- 负责人与交付
